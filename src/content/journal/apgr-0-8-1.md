I added footprint accounting in APGR 0.8.1 so context size can become an explicit input to a decision. Descriptions, skill bodies and support material all occupy space; I want that cost to be inspectable.

## What this release means to me

A footprint is an accounting result. I do not treat it as a provider-token benchmark or as proof that a smaller prompt produces better work. Those are different questions with different evidence requirements.

## The release boundary

Versioned schemas cover footprints, comparisons, projections, component registries and capacity mappings. The release retains thirty-nine canonical skills, reusable Go packages and deterministic multi-registry packaging.
