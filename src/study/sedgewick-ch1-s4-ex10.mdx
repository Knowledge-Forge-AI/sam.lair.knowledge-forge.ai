## Lower-bound binary search

The Java method searches an inclusive candidate interval
`[lo, hi]`, initially covering the non-empty array. If the key is greater
than the midpoint value, every position through the midpoint can be
discarded, so the lower bound becomes `lo = mid + 1`. Otherwise the
midpoint may still be the first matching position, so the upper bound becomes
`hi = mid`. Because the loop runs while `lo < hi`, each iteration reduces the
interval until it converges on one candidate index.

The midpoint is computed as follows:

<Equation id="sedgewick-ch1-s4-ex10-midpoint" tag="midpoint">

$$
mid = lo + \left\lfloor \frac{hi - lo}{2} \right\rfloor
$$

</Equation>

After convergence, the final equality check returns the candidate index or
`-1` when the key is absent. For a sorted array with duplicates, retaining
`hi = mid` when the midpoint is equal preserves the possibility of an earlier
match. The search performs `O(log n)` comparisons under the source's
ascending, non-empty `int[]` precondition and does not modify the array.
